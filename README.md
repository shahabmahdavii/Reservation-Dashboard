# پنل مدیریت رزروها (Reservio)

پنل مدیریت رزرو برای یک مجموعه خدماتی، همراه با صفحه ورود، داشبورد آماری، جدول رزروها، جست‌وجو، فیلتر، مشاهده جزئیات و ثبت رزرو جدید.
رابط کاربری **دوزبانه (فارسی / انگلیسی)** است و چیدمان با تغییر زبان به‌صورت خودکار بین **RTL و LTR** جابه‌جا می‌شود.

## لینک‌ها

- **نسخه آنلاین (دمو):** https://reservation-dashboard-shahab.surge.sh
- **مخزن گیت‌هاب:** https://github.com/shahabmahdavii/Reservation-Dashboard

## اجرا

پیش‌نیاز: Node.js نسخه ۲۰ یا بالاتر

```bash
npm install
npm run dev
```

آدرس: `http://localhost:5173`

سایر دستورها:

| دستور                  | کاربرد                       |
| ---------------------- | ---------------------------- |
| `npm run build`        | بررسی تایپ و بیلد production |
| `npm run preview`      | اجرای خروجی بیلد             |
| `npm run lint`         | اجرای oxlint                 |
| `npm run typecheck`    | بررسی تایپ با tsc            |
| `npm run format`       | فرمت کل پروژه با Prettier    |
| `npm run format:check` | فقط بررسی فرمت               |

### Git hooks

با `npm install`، **Husky** به‌صورت خودکار نصب می‌شود. قبل از هر commit، هوک `pre-commit` اجرا می‌شود:

1. **lint-staged:** روی فایل‌های stage‌شده `oxlint` و `prettier --write` را اجرا می‌کند.
2. **typecheck:** با `tsc -b` تایپ‌ها را بررسی می‌کند.

اگر یکی از این مراحل خطا بدهد، commit انجام نمی‌شود.

## تکنولوژی‌ها

| ابزار                              | دلیل انتخاب                                                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **React 19 + Vite**                | پروژه کاملاً سمت کلاینت است و به SSR نیازی ندارد؛ Vite سریع و ساده است.                                                               |
| **TypeScript**                     | تایپ‌های دامنه (رزرو، وضعیت، خدمت) و حتی کلیدهای ترجمه تایپ‌شده‌اند.                                                                  |
| **Tailwind CSS v4**                | استایل‌دهی سریع؛ با کلاس‌های منطقی (`ps-*`، `me-*`، `start-*`، `text-start`) یک کد واحد هم در RTL و هم در LTR درست نمایش داده می‌شود. |
| **react-router-dom**               | مسیرهای `/login` و `/dashboard` و محافظت از مسیر داشبورد.                                                                             |
| **Prettier + Husky + lint-staged** | فرمت یکدست کد (همراه با `prettier-plugin-tailwindcss` برای مرتب‌سازی کلاس‌ها) و جلوگیری از commit کد دارای خطای lint یا تایپ.         |
| **i18next + react-i18next**        | ترجمه‌ها در دو فایل `fa.json` و `en.json`؛ کلیدها با `CustomTypeOptions` تایپ‌شده‌اند و کلید اشتباه خطای کامپایل می‌دهد.              |

بک‌اند وجود ندارد: احراز هویت نمایشی است و داده‌ها در State (Context) نگه‌داری و در `localStorage` ذخیره می‌شوند تا با رفرش صفحه از بین نروند.

## امکانات

- **ورود:** اعتبارسنجی فیلدهای خالی، ایمیل نامعتبر و طول رمز؛ نمایش خطای اطلاعات اشتباه؛ نمایش/پنهان کردن رمز؛ هدایت به داشبورد پس از ورود موفق؛ حفظ نشست.
- **داشبورد:** کارت‌های آماری (قابل کلیک به‌عنوان فیلتر)، جدول ۱۲ رزرو نمونه، جست‌وجو بر اساس نام / شماره تماس / کد رزرو (اعداد فارسی هم پشتیبانی می‌شوند)، فیلتر وضعیت.
- **جزئیات رزرو:** نمایش کامل اطلاعات در Modal و امکان تغییر وضعیت.
- **ثبت رزرو جدید:** فرم در Modal (روی موبایل به‌شکل Bottom Sheet) با اعتبارسنجی نام، شماره موبایل ایران، نوع خدمت، تاریخ (نه در گذشته) و ساعت.
- **پیام‌ها:** Toast برای موفقیت، خطا و اطلاعات.
- **چندزبانه و RTL/LTR:** تاریخ در فارسی به تقویم شمسی و ارقام فارسی نمایش داده می‌شود؛ زبان انتخاب‌شده ذخیره می‌شود.
- **واکنش‌گرا:** جدول در دسکتاپ و کارت در موبایل.
- **دسترس‌پذیری:** `label` و `aria-invalid` / `aria-describedby` برای فیلدها، بستن Modal با Esc و بازگرداندن فوکوس.

## ساختار پروژه

هر پوشه یک **barrel file** (`index.ts`) دارد و ایمپورت‌ها از طریق alias `@/` انجام می‌شوند (مثلاً `import { Button } from '@/components'`).

هر کامپوننت یک پوشه هم‌نام با خودش دارد و کد آن داخل `index.tsx` است. همه کامپوننت‌ها از `components/index.ts` export می‌شوند. داخل `components`، کامپوننت‌ها یکدیگر را مستقیم از پوشه هم (مثلاً `../Button`) ایمپورت می‌کنند تا وابستگی چرخشی از طریق barrel ایجاد نشود.

```
src/
├── components/
│   ├── Button/
│   │   └── index.tsx
│   ├── Header/
│   │   └── index.tsx
│   ├── ...
│   └── index.ts
├── constants/
├── context/
├── data/
├── hooks/
├── i18n/
│   ├── locales/
│   │   ├── fa.json
│   │   └── en.json
│   ├── config.ts
│   ├── i18next.d.ts
│   └── index.ts
├── pages/
├── routes/
├── types/
└── utils/
```

| پوشه         | محتوا                                                                              |
| ------------ | ---------------------------------------------------------------------------------- |
| `components` | همه کامپوننت‌های UI، layout و رزرو                                                 |
| `constants`  | ثابت‌ها، از جمله `ROUTES` (مسیرهای برنامه)                                         |
| `context`    | Context و Provider برای Auth، Reservations و Toast                                 |
| `data`       | داده‌های نمونه و کاربر آزمایشی                                                     |
| `hooks`      | `useAuth`، `useReservations`، `useToast`، `useLanguage`، `useFilteredReservations` |
| `i18n`       | راه‌اندازی i18next، فایل‌های ترجمه و تایپ کلیدهای ترجمه                            |
| `pages`      | `LoginPage` و `DashboardPage`                                                      |
| `routes`     | `AppRoutes` و `ProtectedRoute`                                                     |
| `types`      | تایپ‌های دامنه                                                                     |
| `utils`      | تاریخ، ارقام، اعتبارسنجی، localStorage و کلاس‌های مشترک استایل                     |

### نکات فنی

- **جابه‌جایی RTL/LTR:** با رویداد `languageChanged` در i18next، ویژگی‌های `lang` و `dir` روی تگ `<html>` تنظیم می‌شوند؛ چون همه فاصله‌ها و موقعیت‌ها با کلاس‌های منطقی نوشته شده‌اند، کل چیدمان بدون کد اضافه برعکس می‌شود. آیکون‌های جهت‌دار با `rtl:-scale-x-100` قرینه می‌شوند.
- **اعتبارسنجی:** توابع خالص در `utils/validation.ts` که به‌جای متن، **کلید ترجمه** برمی‌گردانند؛ بنابراین پیام خطا مستقل از زبان است و با تغییر زبان، خطاهای نمایش داده‌شده هم ترجمه می‌شوند.
- **حذف داده‌های ذخیره‌شده:** برای برگشت به داده‌های نمونه، کلید `app.reservations` را از `localStorage` پاک کنید.
